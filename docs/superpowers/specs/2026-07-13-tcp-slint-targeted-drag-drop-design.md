# Borderless TCP-Only、Slint UI 与双向定点拖放设计

日期：2026-07-13

## 背景

Borderless 当前已经具备 Windows 局域网内的键鼠共享、剪贴板同步和批量文件传输能力，但网络层同时维护 TCP、KCP 和独立 UDP 指针通道，配置、运行时、界面与测试中存在大量分支。项目的使用场景是同一局域网内的两台 Windows 电脑，TCP 的稳定性和可维护性更符合当前目标。

当前界面基于 `eframe/egui`，功能可用但信息层级较弱。文件拖放代码处于未收口状态：核心状态机未接入运行时、目标路径直接出现在批量传输清单中、发送端和接收端的完成状态不一致，并且尚未形成可构建、可验收的双向闭环。

本次重构把这三个问题作为一个连续交付处理：先建立 TCP-only 稳定基线，再迁移 Slint 中文界面，最后完成双向定点文件拖放。

## 目标

- 删除 KCP、可靠 UDP 和独立 UDP 指针通道，仅保留 TCP。
- 旧配置能够无感加载，并在下次保存时移除废弃字段。
- 使用 Slint 构建中文双栏控制台，保持原生 Windows 桌面体验和单一可执行程序交付。
- 支持控制端到被控端、被控端到控制端的双向文件与文件夹拖放。
- 文件跨过共享边缘后只同步鼠标和按键；目标端松开左键并解析目录成功后才开始传输。
- 支持桌面、资源管理器当前目录和鼠标下的文件夹图标。
- 跨机拖放始终复制源文件；同名目标自动重命名，绝不覆盖。
- 双方只在接收端完成校验和最终落盘后显示成功。
- 取消、断线和失败能够恢复输入状态并清理未完成临时文件。

## 非目标

- 不支持向浏览器、聊天软件、邮件客户端等任意应用模拟远程 OLE 文件拖放。
- 不支持 Outlook 虚拟附件等非 `CF_HDROP` 数据源。
- 不支持移动语义，不在成功后删除源文件。
- 不支持断点续传；断线后的操作本次失败，用户重新拖放即可。
- 不增加多设备拓扑、账户体系、互联网中继或新的配对认证机制。
- 不迁移到 Tauri/WebView，也不保留两套 UI 框架。

## 交付顺序

1. TCP-only 网络和配置基线。
2. Slint 中文双栏控制台。
3. 核心拖放状态机与协议升级。
4. Windows 边缘捕获和精确落点解析。
5. 双向协调、错误恢复和两机验收。

每一阶段都必须保持可构建和自动测试可运行，后续阶段不得依赖未验证的半成品分支。

## 总体架构

### 模块边界

- `borderless-core`
  - TCP-only 配置模型。
  - 协议版本和线消息。
  - 唯一的 `DragDropSession` 状态机。
  - 与平台无关的拖放目标、传输用途和错误类型。
- `borderless-net`
  - 控制 TCP 客户端和服务端。
  - 带帧消息读写、心跳、断线检测和重连。
  - 独立批量 TCP 文件传输。
  - 授权目标传输所需的目的地引用，不接触 Windows Shell。
- `borderless-win`
  - 键鼠 Hook 和输入注入。
  - `CF_HDROP` 边缘拖拽捕获。
  - 桌面与资源管理器落点解析。
- `borderless-app`
  - 会话生命周期、剪贴板、批量传输和拖放协调。
  - Slint UI 桥接。
  - 将运行时状态投影为稳定的 UI 状态快照。

### 运行线程

- Slint 主线程只负责界面和用户回调。
- Tokio 运行时负责控制 TCP、批量 TCP、心跳、重连与异步文件 I/O。
- Windows Hook、OLE 和 Shell COM 在满足其线程模型的专用线程中运行。
- UI 与运行时继续通过命令和事件通信，不允许 Slint 回调直接执行网络或文件 I/O。

## TCP-Only 网络设计

### 删除范围

- 删除工作区和 `borderless-net` 中的 `kcp-tokio` 依赖及锁文件条目。
- 删除 `kcp_transport.rs` 和 `latest_pointer.rs`。
- 删除 `TransportMode`、`pointer_port`、UDP 地址辅助方法和相关验证。
- 删除 `SendLatestPointer`、`LatestPointer`、`StalePointerPackets` 等仅服务 UDP 的命令、事件、状态字段和日志。
- 删除 GUI 中的传输模式选择、Pointer UDP 端口和 KCP 说明。
- 删除 KCP/UDP 专用测试和手工验收项。

### 保留行为

- 控制连接使用 `TcpFramedTransport`，启用 `TCP_NODELAY`。
- 所有键盘、鼠标、心跳、剪贴板控制和拖放协调消息都走控制 TCP。
- 文件内容继续使用独立的批量 TCP 端口，避免大文件阻塞控制通道。
- 心跳、可靠读超时、断线事件和重连退避继续保留。

### 鼠标移动背压

TCP 可靠传输不能无限积压鼠标移动。`RemoteInputSendBuffer` 改为与传输模式无关：

- 键盘、鼠标按键、滚轮和 `ReleaseAll` 必须保持顺序并立即入队。
- 连续鼠标移动只保留最新待发送位置。
- 在可靠事件入队前先刷新已有的最新鼠标位置，避免点击落在旧坐标。
- 发送队列必须有界；连接阻塞时允许丢弃中间移动，不允许丢弃按键或释放事件。

### 配置迁移

从 `ControllerConfig` 和 `AgentConfig` 中移除 `transport_mode` 与 `pointer_port`。Serde 默认忽略旧 TOML 中未知字段，因此：

- 旧的 `transport_mode = "tcp"`、`transport_mode = "kcp"` 和 `pointer_port` 均不会阻止启动。
- 所有旧配置加载后都固定使用 TCP。
- 用户下一次保存设置时，废弃字段不会再写回。
- `config.example.toml` 和 README 只描述控制 TCP 端口和批量 TCP 端口。

## Slint UI 设计

### 技术选择

- 使用 Slint 原生 Rust 框架，删除 `eframe` 和 `egui` 依赖。
- 使用 `.slint` 声明式文件定义布局、组件和主题。
- 图标使用 Lucide 风格的本地 SVG 资产，不使用字体字符模拟工具图标。
- 保持 Windows 单一可执行程序交付，不引入 WebView 和前端工具链。

### 主窗口

采用已确认的中文双栏控制台：

- 顶栏
  - Borderless 品牌。
  - 连接状态、TCP、延迟。
  - 设置图标和“停止共享”按钮。
- 左栏：连接设置
  - 控制端/被控端分段控件。
  - 控制端显示目标 IP、TCP 端口和目标电脑方位。
  - 被控端显示监听 IP 和 TCP 端口。
  - 文本、富文本、图片、复制文件和文件拖放开关。
  - 保存设置命令。
- 右栏：实时状态
  - 两台电脑连接关系。
  - 当前控制权和跨边缘提示。
  - 文件传输进度、速度、目标摘要和取消命令。
  - 最近活动与明确错误。

界面保持紧凑、安静、适合长期打开。主窗口不使用营销式大标题、装饰性渐变或嵌套卡片。

### UI 桥接

- `RuntimeHandle` 继续暴露命令发送和事件排空接口。
- 新增 UI bridge，把 `AppStatus` 映射为 Slint 属性和模型。
- Slint 回调只产生 `Start`、`Stop`、`Save`、`Reconnect` 和 `CancelTransfer` 等命令。
- Tokio 或 Hook 线程通过 `slint::invoke_from_event_loop` 安排 UI 更新，不跨线程直接持有组件引用。
- 窗口关闭前发送停止命令，确保本机 Hook 恢复为透传并释放远程按键。

## 双向定点拖放设计

### 相邻边缘

控制端配置 `remote_position`。协议握手完成后，控制端把布局关系发送给被控端：

- 控制端监听指向被控端的共享边缘。
- 被控端监听其相反边缘。
- 未连接时不启用边缘 OLE 接收区，避免无效截获本机拖拽。
- 连接或布局变化时安全卸载旧接收区并安装新接收区。

### 唯一状态机

运行时必须使用 `borderless-core::DragDropSession`，不得再维护第二套近似状态。状态为：

1. `LocalDragDetected`
2. `RemoteTargetSelecting`
3. `RemoteDropReleased`
4. `RemoteTargetResolved`
5. `Transferring`
6. `Completed`
7. `Cancelled`
8. `Failed`

会话携带：

- `session_id`
- `transfer_id`
- 拖放方向
- 源路径集合
- 当前状态
- 目标授权引用（解析成功后才存在）

同一端同一时间只允许一个活动拖放会话。新会话到达时若旧会话未结束，应拒绝新会话并保留旧会话状态。

### 源端流程

1. OLE 边缘接收区读取 `CF_HDROP` 本机绝对路径。
2. 验证路径存在且至少包含一个文件或目录，创建会话，但不读取文件内容。
3. 跨过共享边缘后，原生 OLE 拖拽停留在源端边缘；鼠标移动和按键状态通过控制 TCP 交给目标端。
4. 用户在目标端松开左键，协调器记录最后目标坐标并结束源端原生拖拽。
5. 收到目标授权后，重新验证源路径、构建文件清单并检查大小限制。
6. 通过批量 TCP 发送文件树和内容。
7. 只有收到目标端最终结果消息后才进入 `Completed`。

源端注入的 OLE 结束事件必须带注入标记，并由 Hook/协调器过滤，避免把同一次左键释放重复发送给目标端。

### 目标端流程

1. 接收远程鼠标移动并显示真实目标光标。
2. 接收左键释放坐标，在线程正确的 COM 上下文中调用落点解析器。
3. 解析成功后验证目录仍存在且可写，注册一次性目标授权。
4. 返回授权标识和仅供显示的目录摘要，不返回可被源端修改后重新提交的绝对路径。
5. 批量接收器收到拖放清单时消费授权，以本机注册的路径作为唯一目标。
6. 写入临时文件、校验哈希并原子重命名。
7. 所有顶层项目完成后发送最终成功；任一失败发送原因并清理临时文件。

### 精确落点解析

解析顺序为：

1. 桌面或资源管理器中鼠标下的文件夹图标，且该 Shell 项具有真实文件系统目录。
2. 资源管理器窗口当前显示的文件系统目录。
3. 桌面空白区域对应的用户桌面目录。
4. 明确失败。

“此电脑”、快速访问、搜索结果、压缩包内部和其他没有可写文件系统路径的 Shell 位置必须失败，不回退到缓存目录。

Windows 实现应把 Shell COM 查询封装在 `drop_resolver` 内部，向运行时只暴露 `resolve_drop_target(point) -> Result<DropTarget>`。

### 目标授权

批量传输清单不得包含接收端绝对目录。目标端维护一个内存授权注册表：

- 键：`session_id` 与随机一次性令牌。
- 值：已解析绝对目录、过期时间和预期 `transfer_id`。
- 授权只能消费一次。
- 取消、断线、停止或超时立即删除授权。
- 批量接收器只能使用成功消费的本机授权路径。

批量清单使用目的地枚举：

- `IncomingCache`：复制粘贴文件。
- `AuthorizedDrop { session_id, authorization }`：定点拖放。

这避免已连接对端通过构造清单向任意可写本机路径落盘。

### 文件放置

- 始终复制，不删除或移动源文件。
- 多文件和文件夹保留相对目录结构。
- 顶层同名冲突使用 `name (Borderless N).ext`。
- 每个文件写入同目录下的 `.borderless-part` 临时文件。
- 大小和 BLAKE3 校验通过后才原子重命名为最终名称。
- 空目录必须被创建并计入完成条件。
- 任何失败都不得覆盖已有文件。

## 协议设计

协议版本从 `1` 升级到 `2`。新旧程序在 Hello 阶段明确拒绝，不允许握手成功后再因消息结构不同而解码失败。

控制消息包括：

- `PeerLayout { remote_position }`
- `DragDropEntered { session_id, transfer_id, item_count }`
- `DragDropReleased { session_id, point }`
- `DragDropTargetResolved { session_id, authorization, display_name }`
- `DragDropTargetFailed { session_id, reason }`
- `DragDropTransferStarted { session_id, transfer_id }`
- `DragDropCancel { session_id, reason }`
- `DragDropTransferResult { session_id, transfer_id, ok, reason }`

消息必须验证活动会话 ID、允许的当前状态和预期方向。过期、重复或乱序消息记录诊断日志后忽略，不得改变当前会话。

## 错误处理与恢复

### 松开前

- Escape、拖回源端、停止应用或断线：会话取消，不创建目标文件。
- 恢复本机 Hook 透传，向远端发送 `ReleaseAll`，清空按键和鼠标按下状态。

### 目标解析

- 找不到支持的落点、目录不可写或 COM 查询失败：目标端发送明确失败原因，不开始批量传输。
- 目标授权在短时间内未被使用则自动过期，状态进入失败。

### 传输期间

- 源文件消失或变化：失败并通知目标端。
- 目标目录消失、权限变化、磁盘写入失败或哈希不匹配：删除本次临时文件并通知双方失败。
- 断线：本次会话失败，删除未完成临时文件，不自动续传。
- 用户取消：双方标记取消，停止读取/写入并清理临时文件。

### 停止与重连

- 停止应用必须先恢复 Hook、释放输入、撤销 OLE 注册并取消授权，再终止异步任务。
- 重连创建新的连接世代；旧世代的拖放、指针或完成消息全部忽略。

## 状态与日志

Slint UI 展示以下拖放状态：

- 文件已到达共享边缘
- 正在选择目标目录
- 正在解析目标目录
- 正在传输到目标
- 已完成
- 已取消
- 失败及原因

发送端和接收端共享同一个 `transfer_id`，但只有接收端的 `DragDropTransferResult` 能把发送端状态改为完成。`Sent` 仅表示字节已经写入 TCP，不表示目标落盘成功。

### 核心与配置

- 状态机合法和非法转换。
- 取消与失败终态。

- 协议版本不匹配明确失败。
- 所有拖放控制消息编码、解码和消息类型稳定。

### TCP 与批量传输

- TCP 控制回环、断线、超时和重连。
- 鼠标移动合并不改变按键事件顺序。

## 完成标准

- 产品代码、配置示例和 Cargo 依赖中不存在 KCP、UDP 指针或 `pointer_port`。
- 旧 KCP 配置启动后实际使用 TCP，并能保存为新格式。
- `cargo fmt --all -- --check` 通过。
- `cargo test --workspace` 通过。
- `cargo clippy --workspace --all-targets -- -D warnings` 通过。
- `cargo build --release -p borderless-app` 通过。
- 当前拖放原型中的重复状态机、未使用消息和旧参考文件被删除。
- Windows 两机验收清单有实际结果记录。
- 发布包包含新可执行文件、配置示例和更新后的 README。
