# Windows 局域网键鼠共享设计

日期：2026-07-02

## 目标

开发一个在局域网内让两台 Windows 电脑共用一套键盘和鼠标的工具。第一版聚焦核心体验：主控电脑使用真实键鼠，鼠标越过屏幕边缘后，键盘和鼠标控制权无缝切换到受控电脑；鼠标从受控电脑对应边缘返回后，控制权回到主控电脑。

第一版只支持 Windows 到 Windows，不使用 Docker 开发环境，包含完整可用的 GUI 配置和运行界面，并包含键鼠共享、剪贴板同步、跨机复制粘贴和真实文件拖拽。范围排除自动发现、账号系统和互联网远程控制。

## 技术栈

第一版采用 Rust 本机开发，输出一个 Windows GUI 程序。两台电脑运行同一个可执行文件，通过界面配置决定角色和连接目标。程序保留调试日志和少量命令行参数，但普通使用路径以 GUI 为主。

选择 Rust 的原因：

- 适合实现低延迟输入事件处理和网络通信。
- 内存安全，适合长期运行的后台工具。
- 可以通过 `windows` crate 调用 Windows API。
- 核心能力和 GUI 都可以放在同一个 Rust workspace 中，减少额外工具链。

核心依赖方向：

- Rust edition 2021 或更新版本。
- `eframe` / `egui`：实现第一版 Windows 图形界面。
- `windows` crate：调用 Windows hook、`SendInput`、显示器枚举、DPI 相关 API。
- `tokio`：TCP、UDP、心跳、重连、异步任务。
- `kcp-tokio`：KCP over UDP 可靠传输，用于低延迟模式下的键盘、鼠标按键、滚轮和控制消息。
- `serde` + `toml`：读取配置文件。
- `tracing` + `tracing-subscriber`：日志和调试输出。
- `bytes` 或手写轻量编解码：二进制协议打包。
- `blake3`：文件传输分块校验和整文件校验。
- `uuid`：剪贴板变更、文件传输、拖拽会话 ID。
- `walkdir`：目录复制和拖拽时展开目录文件清单。

第一版选择 `egui` 而不是 Tauri，是为了避免一开始引入 Node、前端构建链和 WebView 调试复杂度。GUI 主要承担配置和状态展示，不进入键鼠事件热路径。

## 运行模式

程序支持两个角色：

- `controller`：主控端，运行在插着真实键鼠的电脑上。负责捕获本机键鼠事件、判断边缘切换、维护控制状态、向受控端发送输入事件。
- `agent`：受控端，运行在被控制的电脑上。负责接收输入事件，并通过 Windows `SendInput` 注入到本机桌面。

第一版允许两台电脑都安装同一个程序，但一个配置为 `controller`，另一个配置为 `agent`。本版目标是把两台 Windows 电脑之间的 GUI 配置、连接、四向边缘切换、键鼠事件传输、断线恢复、日志和验收打通。双向互控和多电脑拓扑不进入本版。

## 配置

GUI 负责编辑配置，并持久化到 `config.toml`。配置文件仍然保留，方便调试、备份和手动修改。

主控端配置包含：

- 当前角色：`controller`
- 受控端 IP 和端口
- 受控端相对主控端的位置：`left`、`right`、`top`、`bottom`
- 传输模式：`tcp` 或 `kcp`
- KCP 模式下的高频鼠标 UDP 端口，默认使用主端口加 1
- 大文件传输 TCP 端口，默认使用主端口加 2
- 边缘触发宽度，默认 2 像素
- 是否启用剪贴板同步
- 是否同步文本、HTML、图片
- 是否启用跨机文件复制粘贴
- 是否启用真实文件拖拽
- 单次剪贴板最大字节数
- 单次文件传输最大字节数
- 收到远程文件后的缓存目录
- 是否启用调试日志

受控端配置包含：

- 当前角色：`agent`
- 监听地址和端口
- 传输模式：`tcp` 或 `kcp`
- KCP 模式下的高频鼠标 UDP 监听端口，默认使用主端口加 1
- 大文件传输 TCP 监听端口，默认使用主端口加 2
- 是否启用剪贴板同步
- 是否同步文本、HTML、图片
- 是否启用跨机文件复制粘贴
- 是否启用真实文件拖拽
- 单次剪贴板最大字节数
- 单次文件传输最大字节数
- 收到远程文件后的缓存目录
- 是否启用调试日志

## GUI 范围

第一版 GUI 必须覆盖完整使用闭环：配置角色、建立连接、启动停止、查看状态、观察延迟、定位常见错误。界面风格保持工具型，不追求复杂动画或营销式视觉。

主界面包含：

- 角色选择：`controller` 或 `agent`
- 主控端连接设置：受控端 IP、端口、相对位置
- 受控端监听设置：监听地址、端口
- 传输模式选择：稳定模式 `TCP`、低延迟模式 `KCP`
- KCP 模式的 UDP 鼠标端口提示和防火墙提示
- 大文件传输端口、缓存目录、大小限制配置
- 剪贴板同步开关：文本、HTML、图片
- 跨机文件复制粘贴开关和传输进度
- 真实文件拖拽开关、拖拽会话状态和失败提示
- 四向布局选择：`left`、`right`、`top`、`bottom`
- 边缘触发宽度设置
- 启动、停止、重连按钮
- 当前状态：未启动、等待连接、已连接、本机控制、远程控制、断线重连
- 延迟显示：最近 RTT、平均 RTT
- 简短事件日志：连接、断线、切换、权限错误、注入失败

GUI 线程只负责展示状态和发送控制命令。键鼠捕获、输入注入和网络发送不经过 GUI 线程，避免界面卡顿影响输入延迟。

## 架构

代码分为九个主要模块：

1. `ui`
   - 使用 `egui` / `eframe` 实现主窗口。
   - 编辑配置并保存到 `config.toml`。
   - 展示连接状态、延迟、事件日志和错误提示。
   - 向后台运行时发送启动、停止、重连等命令。

2. `config`
   - 读取和校验 `config.toml`。
   - 把字符串配置转换为强类型结构。

3. `protocol`
   - 定义网络消息类型和二进制编解码。
   - 负责输入事件、心跳、握手、错误通知的序列化。

4. `net`
   - 管理传输层抽象、TCP 连接、KCP 连接、UDP 最新鼠标坐标通道和大文件传输 TCP 通道。
   - 主控端负责连接受控端。
   - 受控端负责监听并接收连接。
   - 提供发送队列、心跳、断线检测、重连和传输模式状态。

5. `win_input`
   - 主控端使用 `WH_MOUSE_LL` 和 `WH_KEYBOARD_LL` 捕获全局鼠标、键盘事件。
   - 主控端在远程控制激活时抑制本机输入事件。
   - 受控端使用 `SendInput` 注入鼠标和键盘事件。
   - 负责枚举虚拟桌面范围和 DPI 感知设置。

6. `control`
   - 控制状态机。
   - 判断是否进入远程控制。
   - 维护远程虚拟鼠标坐标。
   - 判断是否从远程桌面边缘返回。
   - 处理断线后的按键释放和状态恢复。

7. `clipboard`
   - 监听 Windows 剪贴板变更。
   - 读取和写入文本、HTML、图片、文件列表和自定义远程文件引用。
   - 使用变更 ID 和来源设备 ID 避免两端互相回写造成循环。

8. `file_transfer`
   - 管理文件清单、目录展开、分块传输、进度、取消、重试和校验。
   - 文件内容走单独 TCP 大流量通道，不占用键鼠低延迟通道。
   - 收到文件后写入缓存目录，并把本地缓存路径暴露给剪贴板或拖拽模块。

9. `drag_drop`
   - 在主控端配置边缘创建 Windows Shell/OLE 拖拽交接区域。
   - 读取本机拖拽的 `CF_HDROP` 文件列表。
   - 在受控端用已缓存文件创建远程拖拽源，让用户能拖到远程 Explorer 或支持文件拖放的应用中。

模块边界保持清晰：`ui` 不处理原始输入事件，`win_input` 不关心网络，`net` 不关心 Windows API，`control` 通过输入事件和连接状态驱动键鼠业务逻辑。`clipboard`、`file_transfer`、`drag_drop` 通过明确的消息和传输会话互通，不进入键鼠热路径。

## 输入捕获

主控端通过 Windows 低级 hook 捕获输入：

- 鼠标：`WH_MOUSE_LL`
- 键盘：`WH_KEYBOARD_LL`

当控制状态为本机模式时，事件继续传递给 Windows，主控端只观察鼠标是否抵达配置方向的屏幕边缘。

当控制状态为远程模式时，主控端把鼠标移动、点击、滚轮、键盘按下和键盘释放事件转换为协议消息并发送给受控端，同时拦截这些事件，避免它们继续作用于主控电脑。

为避免程序崩溃或断线时出现按键卡住，主控端和受控端都维护当前按下的键集合。连接断开、退出程序或发生错误时，受控端会释放所有仍处于按下状态的按键和鼠标按钮。

## 输入注入

受控端使用 `SendInput` 注入事件。

鼠标移动第一版使用绝对坐标注入，坐标按受控端虚拟桌面矩形映射。鼠标按钮、滚轮和键盘事件按接收顺序注入。

限制：

- 普通权限程序通常不能向管理员权限窗口注入输入。
- 第一版要求两端程序以相同权限等级运行。
- 如果用户需要控制管理员窗口，应把两端都以管理员身份运行。第一版不依赖代码签名或 UIAccess 才能完成核心能力；权限不足时 GUI 必须给出明确提示。

## 屏幕边缘切换

程序把每台电脑的所有显示器视为一个虚拟桌面矩形。第一版支持四种相对位置：

- `left`
- `right`
- `top`
- `bottom`

进入远程控制时：

- 如果受控端在右侧，主控端鼠标到达主控虚拟桌面右边缘并继续移动时切换。
- 如果受控端在左侧，主控端鼠标到达左边缘并继续移动时切换。
- 如果受控端在上方，主控端鼠标到达上边缘并继续移动时切换。
- 如果受控端在下方，主控端鼠标到达下边缘并继续移动时切换。

切换坐标按比例映射：

- 左右切换时，把主控端 Y 坐标比例映射到受控端 Y 坐标。
- 上下切换时，把主控端 X 坐标比例映射到受控端 X 坐标。

远程控制期间，主控端维护一个远程虚拟坐标。收到真实鼠标移动 delta 后，更新远程虚拟坐标并发送给受控端。当远程虚拟坐标越过返回边缘时，退出远程控制，把主控端鼠标放回对应边缘附近，之后的事件恢复作用于主控电脑。

## 通信方式

第一版包含两种可配置传输模式：

- 稳定模式 `tcp`：一条常驻 TCP 连接，开启 `TCP_NODELAY`。这是默认模式，适合有线局域网或稳定 Wi-Fi。
- 低延迟模式 `kcp`：KCP over UDP 负责可靠、有序事件；单独的 UDP 最新坐标通道负责高频鼠标移动。这个模式适合 Wi-Fi 抖动或轻微丢包场景。

键盘、鼠标按键、滚轮、握手、心跳、错误、`ReleaseAll` 都必须走可靠有序通道。在 `tcp` 模式下，这些事件走 TCP；在 `kcp` 模式下，这些事件走 KCP。

鼠标移动按传输模式处理：

- `tcp` 模式：鼠标移动走 TCP，但发送队列只保留最新位置，避免旧移动事件堆积。
- `kcp` 模式：鼠标移动走 UDP 最新坐标通道。消息带递增序号，受控端只接受比当前序号更新的坐标，旧包和乱序包直接丢弃。

KCP 模式的端口：

- 可靠通道使用配置的主端口。
- 鼠标最新坐标 UDP 通道默认使用主端口加 1，也允许在配置中覆盖。
- GUI 必须提示用户在 Windows 防火墙中放行这两个 UDP 端口。

连接参数：

- TCP 模式开启 `TCP_NODELAY`，减少 Nagle 算法带来的小包延迟。
- KCP 模式使用快速模式：较短 update interval、快速重传、关闭拥塞控制，目标是降低局域网抖动下的尾延迟。
- 输入事件使用二进制协议，避免热路径 JSON 编解码。
- 消息带类型、长度和递增序号，便于调试和检测异常。
- 心跳间隔默认 500ms。
- 超过 1500ms 未收到可靠通道心跳或数据则认为断线。

剪贴板和文件传输使用额外通道：

- 剪贴板元数据、文本、HTML、小图片和文件清单走可靠控制通道。
- 文件内容走单独 TCP 大流量通道，默认端口为主端口加 2。
- 大文件传输按块发送，每块带序号和校验；整文件使用 `blake3` 校验。
- 大文件传输通道限速和队列独立于键鼠通道，拖文件时鼠标键盘仍然保持低延迟。

主要消息：

- `Hello`：握手，交换协议版本和屏幕信息。
- `MouseMoveAbs`：远程绝对鼠标坐标。
- `MouseButton`：鼠标按下或释放。
- `MouseWheel`：滚轮。
- `Key`：键盘按下或释放。
- `Heartbeat`：心跳和延迟估算。
- `ReleaseAll`：释放所有按下状态。
- `Error`：协议错误或不可恢复问题。
- `ClipboardOffer`：剪贴板变更摘要，包含格式、大小、来源和变更 ID。
- `ClipboardData`：剪贴板文本、HTML、图片或远程文件引用。
- `FileTransferOffer`：文件复制粘贴或拖拽产生的文件清单。
- `FileTransferProgress`：文件传输进度。
- `FileTransferComplete`：文件传输完成和校验结果。
- `DragDropStart`：真实拖拽跨屏交接开始。
- `DragDropCancel`：拖拽取消。

## 剪贴板同步

第一版支持 Windows 到 Windows 的双向剪贴板同步。支持格式：

- Unicode 文本。
- HTML Format。
- 图片，优先同步 PNG 或 DIB，超过大小限制时拒绝并提示。
- 文件列表 `CF_HDROP`，用于跨机复制粘贴和文件拖拽。

剪贴板监听使用 Windows 剪贴板更新通知。程序写入远程剪贴板后，会记录本地抑制窗口，避免把自己刚写入的内容再次同步回对端。每次剪贴板变更都有 `change_id`、`source_device_id` 和内容摘要，重复变更直接忽略。

剪贴板默认启用文本和 HTML，同步图片、文件复制粘贴、文件拖拽也在第一版内实现，但 GUI 必须允许用户单独关闭这些能力。超过配置大小限制的内容不会自动传输，GUI 日志给出原因。

## 跨机复制粘贴

跨机复制粘贴基于 `CF_HDROP` 文件列表实现。用户在主控电脑复制文件或目录时，本机读取文件清单并发送 `FileTransferOffer`。对端接收后，把文件传输到缓存目录，校验完成后把对端本地缓存路径写入剪贴板 `CF_HDROP`。这样用户可以在远程 Explorer 或支持文件粘贴的应用中直接粘贴。

目录复制会展开为文件清单并保留相对路径。文件名冲突使用自动重命名策略，例如 `name (Borderless 1).ext`。传输进度、速度、剩余大小、失败文件和取消按钮都显示在 GUI 中。

## 真实文件拖拽

第一版支持从主控端拖拽文件跨过配置屏幕边缘，并在受控端继续拖到 Explorer 或支持 `CF_HDROP` 的应用中。

设计方式：

- 主控端在配置的切换边缘创建透明 OLE 拖拽交接区域。
- 当用户从 Explorer 或支持标准文件拖拽的应用拖动 `CF_HDROP` 文件进入边缘交接区域时，主控端读取文件列表并创建拖拽会话。
- 文件内容通过大文件传输通道发送到受控端缓存目录。
- 受控端收到并校验文件后，创建远程 OLE 拖拽源，使用缓存路径组成 `CF_HDROP` 数据对象。
- 用户继续控制远程鼠标，把拖拽释放到远程 Explorer 或目标应用。

拖拽过程必须支持取消。若文件较大，GUI 显示准备拖拽进度；在文件准备好前，受控端显示拖拽会话状态，键鼠控制仍可停止或返回本机。第一版完整支持标准 `CF_HDROP` 文件拖拽；应用自定义私有拖拽格式不作为验收目标。

## 降低延迟的策略

输入热路径不经过 UI，也不做磁盘写入。

主控端：

- hook 回调尽量短，只把事件投递到无锁或低开销队列。
- 网络发送任务单独运行，避免阻塞 hook。
- 鼠标移动事件可以轻量合并，只发送最新位置，目标间隔约 1 到 2ms。
- 鼠标按键、滚轮和键盘事件不合并，保证顺序和可靠性。

网络层：

- 默认 TCP 长连接，开启 `TCP_NODELAY`。
- KCP 模式用于可靠控制事件，降低无线抖动下的重传等待。
- KCP 模式下鼠标移动使用 UDP 最新状态通道，受控端丢弃旧序号包。
- 二进制协议。
- 尽量减少消息分配和复制。

受控端：

- 网络接收和输入注入分离。
- 可以把同一批到达的输入事件合并为一次 `SendInput` 调用。
- 对鼠标移动使用最新坐标，避免旧移动事件堆积造成拖影。

预期体验目标：

- 局域网内鼠标移动端到端延迟尽量控制在 10ms 以内。
- 键盘和点击事件不丢失、不乱序。
- 断线后 1.5 秒内恢复本机控制并释放远程按键状态。

## 错误处理

必须处理的情况：

- 受控端未启动：主控端持续重连并提示状态。
- 网络断开：释放远程按键，退出远程控制，回到本机模式。
- KCP/UDP 被防火墙阻止：GUI 提示放行可靠端口和鼠标 UDP 端口，并允许切回 TCP 模式。
- UDP 鼠标通道丢包：受控端继续使用最新收到的坐标，不触发可靠通道重传。
- 剪贴板同步循环：通过来源设备 ID、变更 ID 和写入抑制窗口避免回环。
- 剪贴板内容过大：拒绝同步并提示当前大小和配置限制。
- 文件传输中断：保留未完成临时文件，允许重试或清理。
- 文件校验失败：删除失败临时文件，记录错误并允许重新传输。
- 文件名冲突：自动重命名，不覆盖用户已有文件。
- 拖拽交接失败：取消远程拖拽会话，恢复本地和远程输入状态。
- 程序异常退出：尽量在退出处理里发送 `ReleaseAll`。
- 权限不足：检测输入注入失败次数，日志提示以相同权限运行。
- 协议版本不匹配：拒绝连接并输出清晰错误。

第一版日志输出到 GUI 事件面板和本地日志文件。日志中记录连接状态、角色、切换事件、断线事件、平均 RTT 和输入注入错误。调试运行时可以额外输出到控制台。

## 风险与取舍

第一版引入 GUI，但 GUI 只承担配置、启动停止、连接状态和日志展示。真正影响体验的输入捕获、输入抑制、输入注入、边缘切换和网络发送仍然在后台模块中完成，避免 GUI 线程进入热路径。

第一版选择 `egui` 而不是 Tauri，是为了减少额外依赖和安装负担。代价是界面会偏工具型，不追求复杂动画和高度定制视觉。托盘、MSI/EXE 安装器和其他 GUI 框架不影响本版主流程，放在本版之外；便携 release 包进入第一版。

第一版同时支持 TCP 和 KCP，是为了兼顾稳定性和低延迟调试空间。TCP 是默认模式，便于防火墙、诊断和有线局域网使用；KCP 是低延迟模式，用于无线抖动或轻微丢包环境。鼠标移动在 KCP 模式下使用 UDP 最新状态通道，因为高频移动事件更关心“最新位置”而不是“每一个历史位置都可靠送达”。

第一版同时支持剪贴板、文件复制粘贴和真实文件拖拽，因此必须把文件大流量传输从键鼠低延迟通道中拆出来。这样功能完整，但工程复杂度明显增加：需要处理 Windows 剪贴板格式、Shell/OLE 拖拽、文件缓存、校验、取消、冲突命名和防火墙端口提示。

第一版只支持两台电脑，是为了让控制状态机保持清晰。多电脑布局会引入图结构拓扑、路由和更多边界情况，明确放在本版之外。
